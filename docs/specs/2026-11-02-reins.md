# Reins

Date: 2026-11-02
Status: Scope accepted by the owner on 2026-11-02. Two decisions are open (see below). The Loadout
tab exists as a mock-level implementation; Rules and Activity are not built. No execution plan yet.

## Purpose

One local app to control Claude Code and Codex CLI on the owner's Mac. It answers three questions:
what is each agent equipped with, what is it allowed to do, and what did it do.

Three earlier mocks were each too thin to stand alone: `Loadout` (configuration), `Agent Replay
Studio` (history) and `agent-world` (live view). Together they close a loop: see an agent do the
wrong thing, change its permissions or hooks, then check the result.

## Users

A developer or vibe coder who runs agents daily and has accumulated many skills, hooks and
permissions.

## Identity

- Product and app name: `Reins`. `Loadout` was rejected because at least four tools in the same
  category already use it.
- Repository: `spacevibe-reins`, in `spacevibe-workspace`.
- Public site and downloads: `reins.spacevibe.dev`. No DNS record exists yet; adding one needs the
  owner's approval at that time.

## Scope

### Tab: Loadout

- List skills, subagents and hooks of both CLIs, with usage counted from local logs.
- Add, remove and copy between CLIs in one step, with Undo.
- Find dead hooks: the command names script paths and none of them exist.

### Tab: Rules

- Show and edit agent permissions for Claude Code and Codex, globally and per project.
- Every edit can be undone.

### Tab: Activity

- Running sessions: state, current tool, estimated cost.
- Failed commands, with repeated failures grouped into one row with a count.
- File history across sessions.
- Replay Studio findings apply here:
  - Home has one primary list, not three equal columns.
  - A failure title has one consistent form.
  - A junk session title falls back to the first meaningful request, then date and short ID.
  - A worktree slug is not shown as a project name.
  - A file path is shown long enough to tell two files apart.
  - "Next run passed" must not read as proof that the failure was fixed.

## Constraints

- Runs only on the local machine, bound to `127.0.0.1`. No account. No user data leaves the machine.
- Session logs are read-only. Writes go only to agent configuration, and every write can be undone.
- The app never executes a hook or a recorded command.
- Secret values in settings are never read into the UI or logged.

## Out of scope

- A terminal, or sending prompts and replies to an agent. SpaceVibe Deck owns running agents.
- Cloud sync and multiple machines.
- General token or cost analytics.
- Cursor and Gemini.

## Open decisions

- **Stop button in Activity.** It would end a running session's process after a confirmation. The
  recommendation is to include it. It cannot be undone: the current turn stops and work already
  done stays. The owner has not decided.
- **Visual direction.** Directions A, B and C are rendered in the app (`?d=a|b|c`). The
  recommendation is A, with C's route view on hooks. The owner has not picked one.

## To verify before building

- The permission schema of Codex. It has not been read.
- That Claude Code and Codex load what the app writes: added skills, agents, hooks and permissions.
- How each CLI reacts to a termination signal, and whether its log stays resumable (Stop only).
- Live session state for Codex, which has no status file.

## Acceptance criteria

1. Within one minute, the owner can find what permissions an agent has, then remove something
   unneeded or block a behavior, then undo that change.
2. A skill, agent, hook or permission written by the app is honored by a real CLI session in a
   throwaway configuration.
3. Automated tests never write to the real `~/.claude` or `~/.codex`.
4. Activity shows a running session of each CLI, and states plainly what cannot be measured.
5. With no network connection, all three tabs work.
6. The owner approves the UI by eye.

## Known defects to fix

- Hook error count is wrong: the app showed 0 while logs held 20 error records.
- Codex hook runs are not logged, so they cannot be counted.
- Project-level `.claude/` configuration is not read.
- The Codex event list comes from observation only.
