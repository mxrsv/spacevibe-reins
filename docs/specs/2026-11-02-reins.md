## Purpose

One local app to control Claude Code and Codex CLI on the owner's Mac. It answers four questions:
what is each agent equipped with, what is it allowed to do, what did it do, and what did it cost. Limits adds a fifth: how
much of each subscription's usage limit is left.

Reins is first an agent control app. On 2026-11-02 the owner kept token and cost tracking out because TokenTracker
owned it; on 2026-11-03 the owner reversed that so everything lives in one app and TokenTracker can be uninstalled.
Any other feature belongs here when it changes or explains what an agent may do.

Three earlier mocks were each too thin to stand alone: `Loadout` (configuration), `Agent Replay
Studio` (history) and `agent-world` (live view). Together they close a loop: see an agent do the
wrong thing, change its permissions or hooks, then check the result.

## Users

A developer or vibe coder who runs agents daily and has accumulated many skills, hooks and
permissions.

## Platform

Decided by the owner on 2026-11-07 (SV1 to SV8, SV12, SV13), replacing the Swift-library engine decided on 2026-11-02.
Execution: [Go core and identity plan](../plans/2026-11-07-go-core-and-spacevibe-identity.md).

- Two parts. The core is a standalone engine written in Go and lives in this repository, in the directory `core/`
  (SV1, SV6; the name is owner decision D-7 in the plan, recommended and not yet confirmed). The macOS app is Swift and
  SwiftUI and is the UI layer only (AppKit where SwiftUI falls short). The Swift engine library (`ReinsCore`) and the
  `reins-cli` executable are not part of the target design: the core replaces them, and the Swift code is the port source
  until it is deleted.
- Shell-to-core protocol (SV3): JSON-RPC 2.0 over stdio, with the core as a child process owned by the GUI.
  - `initialize` carries the protocol version; a mismatch is refused.
  - Stdout carries protocol only; logs go to stderr.
  - The core exits on stdin EOF.
  - The child is spawned from an argv array, never through a shell.
  - The core opens no network listener (S-R5).
  - A one-shot `spacevibe <command> --json` stays for debugging.
  - The wire format (framing, errors, notifications) is specified in the plan, task PR.1.
- The app reaches the core only through the child process, via one `CoreClient` in Swift; the UI no longer links
  `ReinsCore` (SV4). Migration is one screen at a time.
- Parity (SV5): the Node `core/` and its golden generator are deleted, as plan task S8.3 intended. The existing golden
  files are frozen as committed files. The Go core must match them by canonical bytes of named projections, as defined in
  the plan (conflict C1); the byte-for-byte wording is being narrowed there and needs the owner's explicit yes.
  Bundling Node as a helper was rejected: it would ship a second runtime.
- Order (SV7, SV8): the Go port comes before the first macOS publish, so real-CLI acceptance, write safety and Stop, and
  TCC consent are verified once, on the Go core. The core review is a read-only, severity-ranked report whose findings
  become tasks in an existing plan.
- Main window: `NavigationSplitView` sidebar with Loadout, Agents, Activity, Tokens. A menubar item (`MenuBarExtra`) that shows
  running sessions is a later addition, not part of the first cut. The command palette (`⌘K`) and the toast with Undo
  are custom SwiftUI views.
- Native macOS app built with SwiftPM and the Command Line Tools as in `spacevibe-board`; no Xcode required. Minimum
  macOS 15. The core is built with the Go toolchain.
- Windows and Linux (SV2): the shells are committed within about 3 to 6 months, which is the reason for the Go core
  (owner, 2026-11-07, building on the 2026-11-02 reversal of "Windows is dropped"). They are separate work, outside
  this spec's acceptance criteria. The UI technology for them (native per OS or a shared web UI) is **open** and is needed
  only when the second shell starts.
- Distribution: a signed and notarized app outside the App Store, not sandboxed (it must read and write
  `~/.claude`, `~/.codex` and project folders). Reading folders under Documents triggers a macOS consent prompt,
  which the app must handle (denied means "not readable", never a crash or a silent empty list).
- Updates: Sparkle, from a signed `appcast.xml` (owner, 2026-11-03, reversing "no updater"). The app checks once a day
  without asking unless the owner turns automatic checks off in Settings (2026-11-04,
  [Settings](2026-11-04-reins-settings.md)), and never installs without a click. Sparkle's standard window shows the update; a check that finds one
  mid-session also shows a toast that opens that window. A build with no feed configured makes no request. Notarizing,
  hosting the public feed and publishing a release are separate release work. For the new bundle id Sparkle gets a new key
  pair, a new Keychain account and a new `SUPublicEDKey` (SV13); installed `v0.1.0` copies are not kept updating (SV11).

## Scope

### Tab: Loadout

- List skills and subagents of both CLIs (and hooks until the Agents cut-over), with usage counted from local logs.
- Add, remove and copy between CLIs in one step, with Undo.
- Hooks, their usage and dead hooks (the command names script paths and none of them exist) move to Agents at its
  cut-over.

### Tab: Agents

Replaces Tab: Rules (owner, 2026-11-05). Requirements in the [Agents spec](2026-11-05-reins-agents.md):
- Every setting of both CLIs is editable from one card per agent, Codex included. This reverses "writing Codex settings
  from the app is out of scope".
- Every save is confirmed once and can be undone.
- Until the cut-over, the Rules tab keeps its current behaviour: Claude Code editable, Codex read only.

### Tab: Activity

- Running sessions: state, current tool, estimated cost. The cost is a small detail on the session's row; history and
  totals live in Tokens.
- Stop a running session's process, after a confirmation. It cannot be undone: the current turn stops and work
  already done stays.
- Failed commands, with repeated failures grouped into one row with a count.
- File history across sessions.
- Replay Studio findings apply here:
  - Home has one primary list, not three equal columns.
  - A failure title has one consistent form.
  - A junk session title falls back to the first meaningful request, then date and short ID.
  - A worktree slug is not shown as a project name.
  - A file path is shown long enough to tell two files apart.
  - "Next run passed" must not read as proof that the failure was fixed.

### Tab: Tokens

- Tokens and estimated cost of both CLIs by day, week, month and total, with Claude Code and Codex shown side by side.
- Top models, and a breakdown by day and by project.
- A day is a local calendar day on the machine. Tokens are kept as input (uncached), cache write, cache read and output,
  with the same meaning for both CLIs: Codex logs its input with cached tokens included, so they are subtracted.
- Cost is labelled as an estimate from the app's price table, not what a subscription costs. A model with no price reads
  as not measured for its share, never as 0.
- History outlives logs: a day, model or project already counted stays when its log disappears, and a rescan never lowers
  a past day. The tab states the date counting starts from. Losing the history file loses only the days whose logs are gone.
- The history file holds names, dates and numbers only, never log text, and is readable only by the owner (mode 0600).

### Limits

Decided by the owner on 2026-11-03: local readings only, Kimi CLI left out of the first cut (it is not installed on the
owner's Mac).

- Shows the subscription usage limits of Claude Code, Codex and Gemini CLI: each window (5-hour, weekly, weekly for one
  model), the share used, when it resets, and when the reading was taken.
- Sources, read-only, with no request, no credential read and no CLI started:
  - Codex: the `rate_limits` of the newest `token_count` event in its rollout logs, written after every turn.
  - Claude Code (owner-approved correction, 2026-11-05): quota received through the supported `statusLine` payload,
    collected into Reins' own data directory by a separate native helper that Claude starts. Installation is explicit,
    preserves the existing status-line command, input, output and settings, and records an undoable journal entry.
    The GUI never starts the helper or the original command. No dependency on another application's capture files.
    The helper persists only known quota windows, receipt time and a hash of the configured account identity; no
    transcript, credentials or raw payload. A changed account invalidates snapshots from the previous account.
    The newest reading wins against the saved `.claude.json` cache. Cache fallback is labelled with its source and age;
    Refresh rereads local files and does not fetch quota. Status-line receipt time is not an upstream fetch timestamp.
    Active status-line snapshots expose the five-hour and all-model weekly windows, not model-scoped weekly quotas.
    A repeating idle session must not lower the highest recent usage for the same window/reset. Missing or invalid
    payloads must not erase a valid reading. A passed reset remains unknown until another reading arrives.
  - Gemini CLI keeps no limit on disk, so it reads as not measurable, with that reason.
- A window whose reset time has passed, a missing cache and a shape the app does not recognise read as unknown, never as
  0% used. Only the window fields and the reading time are shown; account identity is hashed for capture isolation.

## Constraints

- Runs only on the local machine as a native macOS app. The app opens no network listener. Its only network
  requests are the update check and download (see Distribution); it has no crash reporter and no analytics and sends
  no system profile. No account. No user data leaves the machine.
- Session logs are read-only. Writes go only to agent configuration, and every write can be undone. Stop is not
  a write and is the one action with no undo. The app's own data folder (usage cache, token history) is not agent
  configuration and has no undo.
- The app never executes a hook or a recorded command.
- Secret values in settings are never read into the UI or logged; one can be replaced without being shown (Agents spec,
  Writes).

## Out of scope

- A terminal, or sending prompts and replies to an agent. SpaceVibe Deck owns running agents.
- Cloud sync and multiple machines.
- Limit readings that need a network request or a credential: Gemini CLI numbers, a fresher Claude Code reading than its
  own cache. Kimi CLI.
- In Tokens: heatmap, Share, custom date range, a Reasoning column, importing from TokenTracker, and tools other than
  Claude Code and Codex.
- Support for many tools (Cursor, Gemini outside Limits, and others), desktop pets, widgets, achievements and leaderboards.

## To verify before building

- The permission schema of Codex. It has not been read.
- That Claude Code and Codex load what the app writes: added skills, agents, hooks and permissions.
- How each CLI reacts to a termination signal, and whether its log stays resumable (Stop only).
- Live session state for Codex, which has no status file.
- Why TokenTracker's `queue.jsonl` holds 10 duplicated (source, model, hour) keys, before AC8 compares against it.

## Acceptance criteria

1. Within one minute, the owner can find what permissions an agent has, then remove something
   unneeded or block a behavior, then undo that change.
2. A skill, agent, hook or permission written by the app is honored by a real CLI session in a
   throwaway configuration.
3. Automated tests never write to the real `~/.claude` or `~/.codex`.
4. Activity shows a running session of each CLI, and states plainly what cannot be measured.
5. With no network connection, every tab works.
6. The owner approves the UI by eye.
7. Through a local feed, an older signed build finds a newer one with no prompt, then downloads, verifies, installs and
   relaunches it after a click; a wrongly signed update is refused and the old version stays. A build with no feed makes
   no request.
8. For the last 30 full local days on the owner's Mac, Tokens matches TokenTracker per CLI, per day and per token field
   within 1%, or the difference has a stated cause. Cost is not compared: TokenTracker's queue stores no cost.
9. In a test against a temporary home, deleting a counted log and rescanning leaves every past day's numbers unchanged.
10. In a test against a temporary home, Limits reports the Codex and Claude Code windows with the percent and reset time in
    the files and the time of the reading; a passed reset, a missing cache and an unknown shape read as unknown; Gemini CLI
    reads as not measurable; nothing is requested over the network.
