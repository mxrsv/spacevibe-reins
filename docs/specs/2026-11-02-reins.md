# Reins

Date: 2026-11-02
Status: Scope and visual direction (Matrix) accepted by the owner on 2026-11-02. Platform changed the same day from
Electron to native SwiftUI (see Platform).
Execution: [plan](../plans/2026-11-02-reins-swiftui.md). The earlier [Electron plan](../plans/2026-11-02-reins-electron.md)
is superseded.

## Purpose

One local app to control Claude Code and Codex CLI on the owner's Mac. It answers three questions:
what is each agent equipped with, what is it allowed to do, and what did it do.

Reins is an agent control app, not a usage tracker (owner, 2026-11-02, after reviewing TokenTracker, which
already owns token and cost tracking). A feature belongs here when it changes or explains what an agent may do.

Three earlier mocks were each too thin to stand alone: `Loadout` (configuration), `Agent Replay
Studio` (history) and `agent-world` (live view). Together they close a loop: see an agent do the
wrong thing, change its permissions or hooks, then check the result.

## Users

A developer or vibe coder who runs agents daily and has accumulated many skills, hooks and
permissions.

## Identity

- Product and app name: `Reins`. `Loadout` was rejected because at least four tools in the same
  category already use it.
- Repository: `spacevibe-reins`, in `spacevibe-workspace`.
- Public site and downloads: `reins.spacevibe.dev`. No DNS record exists yet; adding one needs the
  owner's approval at that time. Marketing leads with social posts that carry a link, so a domain of its own
  waits until about 500 to 1,000 users back the product. The old address must then redirect.

## Platform

Decided by the owner on 2026-11-02, replacing an Electron decision taken earlier the same day.

- Native macOS app in Swift and SwiftUI (AppKit where SwiftUI falls short), built with SwiftPM and the Command Line
  Tools as in `spacevibe-board`; no Xcode required. Minimum macOS 15. One toolchain, one native look.
- The engine is rewritten in Swift as a library (`ReinsCore`) with no UI dependency. The Node `core/` stays in this
  repository only as a reference oracle until the Swift core matches it on shared fixtures, then it is deleted.
  Bundling Node as a helper was rejected: it would ship a second runtime, the cost SwiftUI is chosen to avoid.
- Main window: `NavigationSplitView` sidebar with Loadout, Rules, Activity. A menubar item (`MenuBarExtra`) that shows
  running sessions is a later addition, not part of the first cut. The command palette (`⌘K`) and the toast with Undo
  are custom SwiftUI views.
- macOS only. Windows is dropped; this reverses the Electron choice, which was made to keep Windows possible.
- Distribution: a signed and notarized app outside the App Store, not sandboxed (it must read and write
  `~/.claude`, `~/.codex` and project folders). Reading folders under Documents triggers a macOS consent prompt,
  which the app must handle (denied means "not readable", never a crash or a silent empty list).

## Interface

Direction "Matrix" chosen by the owner on 2026-11-02. The earlier web prototype directions (`?d=a|b|c`) were
rejected. Click-through mock, outside the repo: `~/scratch/spacevibe-reins/b-matrix.html`.

- Look: macOS System Settings structure (sidebar, inset grouped lists) with a Raycast command palette
  (`⌘K`) and a bottom hint bar. Dark by default, light switchable. Tinted ink ground; the two CLIs carry
  the colour (Claude Code clay, Codex teal); danger and warn colours mark state only.
- Claude Code and Codex are two columns on every tab, so a difference between them is the first thing seen.
- Loadout: one table grouped by Skills, Agents, Hooks; filter chips (All, In one CLI only, Never ran, Dead).
  A missing cell shows "Add to <CLI>" in place. Plugin-owned rows show a lock and no remove.
- Usage cell has five states that must look different: counted (bar and number), never ran (red 0),
  not counted yet (dashed track), not measurable (icon and label, reason on hover), not installed.
- Rules: a capability grid (Read files, Edit files, Run commands, Network, Push and deploy, Secrets), each cell
  Allow / Ask / Deny per CLI, expandable to the concrete rules; a scope selector (Global or a project) and the
  concrete Claude Code rules at that scope below.
- Activity: one lane per CLI for running sessions and failed commands (repeats grouped with a count), and one
  file-history list with the CLI on each row.
- Every write shows a toast with Undo. No Review tab and no inspector pane in this direction.
- Not yet designed: light-mode review, narrow windows, the menubar item, empty and error states.

## Scope

### Tab: Loadout

- List skills, subagents and hooks of both CLIs, with usage counted from local logs.
- Add, remove and copy between CLIs in one step, with Undo.
- Find dead hooks: the command names script paths and none of them exist.

### Tab: Rules

- Show and edit agent permissions for Claude Code and Codex, globally and per project.
- Every edit can be undone.

### Tab: Activity

- Running sessions: state, current tool, estimated cost. The cost is a small detail on the session's row, not
  the start of a tracker.
- Stop a running session's process, after a confirmation. It cannot be undone: the current turn stops and work
  already done stays.
- Failed commands, with repeated failures grouped into one row with a count.
- File history across sessions.
- Replay Studio findings apply here:
  - Home has one primary list, not three equal columns.
  - A failure title has one consistent form.
  - A junk session title falls back to the first meaningful request, then date and short ID.
  - A worktree slug is not shown as a project name.
  - A file path is shown long enough to tell two files apart.
  - "Next run passed" must not read as proof that the failure was fixed.

## Constraints

- Runs only on the local machine as a native macOS app. The app opens no network listener, makes no network
  request, has no updater and no crash reporter. No account. No user data leaves the machine.
- Session logs are read-only. Writes go only to agent configuration, and every write can be undone. Stop is not
  a write and is the one action with no undo.
- The app never executes a hook or a recorded command.
- Secret values in settings are never read into the UI or logged.

## Out of scope

- A terminal, or sending prompts and replies to an agent. SpaceVibe Deck owns running agents.
- Cloud sync and multiple machines.
- General token or cost analytics: usage dashboards, quota and limit tracking.
- Support for many tools (Cursor, Gemini and others), desktop pets, widgets, achievements and leaderboards.

## To verify before building

- The permission schema of Codex. It has not been read.
- That Claude Code and Codex load what the app writes: added skills, agents, hooks and permissions.
- How each CLI reacts to a termination signal, and whether its log stays resumable (Stop only).
- Live session state for Codex, which has no status file.

## Acceptance criteria

1. Within one minute, the owner can find what permissions an agent has, then remove something
   unneeded or block a behavior, then undo that change.
2. A skill, agent, hook or permission written by the app is honored by a real CLI session in a
   throwaway configuration.
3. Automated tests never write to the real `~/.claude` or `~/.codex`.
4. Activity shows a running session of each CLI, and states plainly what cannot be measured.
5. With no network connection, all three tabs work.
6. The owner approves the UI by eye.

## Known defects to fix

- Hook error count is wrong: the app showed 0 while logs held 20 error records.
- Codex hook runs are not logged, so they cannot be counted.
- Project-level `.claude/` configuration is not read.
- The Codex event list comes from observation only.
