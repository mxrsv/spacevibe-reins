# SpaceVibe: support for ten CLIs

Date: 2026-11-19
Status: decided. The owner settled the decisions in an intent interview and a grilling on 2026-11-19. Plan: [2026-11-19-multi-cli](../plans/2026-11-19-multi-cli.md).
Parent: [PRODUCT.md](../../PRODUCT.md), all four jobs. Today every job covers only Claude Code and Codex. This spec widens each job to the CLIs below.

## Intent

- **Outcome:** SpaceVibe supports about ten of the most-used terminal coding CLIs at full depth: inventory (read and write), usage, cost, limits and running sessions. Where a CLI lacks a concept or keeps no log for it, the app says so instead of guessing.
- **User:** developers reached through the `spacevibe.dev` launch who use a CLI other than Claude Code or Codex.
- **Why now:** today the app serves only Claude Code and Codex users, which limits who the launch can reach.
- **Success:** for each CLI, on a real install, a skill or hook added through SpaceVibe is picked up by that CLI itself, Undo restores the file byte for byte, and usage and limits match that CLI's local logs or read "not measurable".
- **Constraint:** every boundary rule in [AGENTS.md](../../AGENTS.md) holds for every CLI (S-R1 to S-R5, R6). Every write keeps a restorable copy. Every CLI has its own synthetic fixture.

## Facts behind the decisions

Researched 2026-11-19. Each wave re-verifies its CLI, because these formats change often.

- **The Gemini CLI consumer tier ended on 2026-06-18 and Antigravity CLI replaced it** ([Google Developers Blog](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)). Enterprise and API-key users keep `~/.gemini`. Antigravity's configuration folder was not documented on that date.
- **Popularity** (stars and npm downloads, indicative only):
  - OpenCode: ~228k stars, 1.5–2.8M a week.
  - Gemini CLI: ~109k stars.
  - Cline: ~69k stars.
  - Goose: ~55k stars.
  - Aider: ~49k stars, no commits since 2026-05.
  - Copilot CLI: 1.2–1.6M a week.
  - Qwen Code: ~31k stars.
  - Kiro CLI: ~3.6k a week.
  - Amp: no local thread log found.
- **Shared formats:** `SKILL.md` is read by Copilot, Droid, Qwen Code, Kiro and OpenCode. `AGENTS.md` is read by Cursor, OpenCode and Kiro. Amp reads `~/.claude/skills`.
- **Hook events differ per CLI:** Gemini CLI has 11, Copilot CLI has 6 (camelCase), and Droid and Qwen Code follow Claude Code's names.
- **Logs:**
  - Copilot: `~/.copilot/session-state/<id>/events.jsonl`.
  - OpenCode: SQLite at `~/.local/share/opencode/opencode.db`, schema undocumented.
  - Gemini CLI: `~/.gemini/tmp/<hash>/chats/`.
  - Droid: `~/.factory/projects/.../*.jsonl`.
  - Token fields: no official schema for Copilot, OpenCode or Gemini CLI.
- **The core today:** both CLIs are hard-coded across `roots`, `config`, `usage`, `inventory`, `mutate`, `activity`, `limits`, `proc`, `statusline` and `rules`. The wire has fixed `claude`/`codex` objects, Swift decodes `cli` as a closed enum, and three places treat an unknown CLI as Codex without any error: `activity/fold-common.go`, `mutate/items.go` and `Components/CLIStyle.swift`. The plan lists the file references.

## Requirements

- **MC-R1. One CLI registry (MC2, MC17, MC27).** The Go registry holds every per-CLI fact: id, label, roots and root env overrides, the concepts and item kinds it supports, the formats its adapter can write, and where its logs live. The shell learns these facts from `clis.list` and holds only each CLI's look. No code outside an adapter branches on a CLI id. An id that has no entry is an error, never a fallback to another CLI.
- **MC-R2. Open contract (MC18, MC27, MC29).** Every per-CLI value on the wire is an entry in an array of `{cli, …}` objects, in registry order. `clis.list` describes every CLI. A copy names its target CLI. A shared item carries `readBy`. Swift decodes an unknown `cli` without failing and does not show it. [core-protocol.md](../internals/core-protocol.md) describes the new shapes.
- **MC-R3. Detection (MC3, MC8, MC9).** A CLI is installed when its configuration folder or its binary on `PATH` exists. Detection starts no process. An installed CLI is on until the owner turns it off.
- **MC-R4. Settings (MC3, MC9).** One group lists all supported CLIs, each with its mark, an on/off switch and "not installed" when it is not installed. Turning a CLI off hides it from every page and every comparison.
- **MC-R5. Inventory per CLI (MC1).** For each enabled CLI, the app reads the concepts that CLI has: skills, subagents, hooks with their events, rules and instruction files, MCP servers, permissions and model. A concept the CLI lacks shows as absent for that CLI: a cell state `absent`, distinct from `missing` (the CLI has the concept, the item is not installed) and from not measurable. It is never shown as 0 and is never offered as a target to add to. Hook rows match across CLIs only on identical event names (MC28).
- **MC-R6. Writes (MC1, MC11).**
  - Each CLI gets add and remove with Undo, plus a restorable copy, as Claude Code and Codex have today.
  - Writes stay inside that CLI's roots.
  - Plugin-owned items, managed settings and any unrecognised format or version are read-only, with a note.
- **MC-R7. Shared files (MC10).** A file that several enabled CLIs read is one row naming every one of them. A write to that row names each CLI it affects before it runs.
- **MC-R8. Copy between CLIs (MC5).** "Add to <CLI>" is offered only when the target CLI reads the source item's format. Otherwise the row says the item cannot be copied to that CLI. The app never converts formats.
- **MC-R9. Usage and cost (MC1, MC12, MC21).** Usage and cost are counted from each CLI's local logs. Hook runs are counted only where the log records them. A model with no price reads as not measured. Where a CLI keeps no local log, usage reads "not measurable" with the reason.
- **MC-R10. Limits (MC1, MC22).** A window is shown only when the CLI's own files or status line input carry it. Otherwise the CLI reads "not measurable", as Gemini does today.
- **MC-R11. Activity (MC16).** Running sessions of each enabled CLI are listed with the existing states. `Stop` sends SIGTERM only to a pid the core found itself and matched to that session (R6).
- **MC-R12. Identity (MC3, MC14, MC23).** Each CLI has a mark and a tone. No tone reuses a state colour or the accent. The owner approves the tones on one specimen sheet before the first wave ships.
- **MC-R13. Safety (Constraint, MC8, MC26).**
  - S-R1 to S-R5 hold for every CLI. Neither the core nor the shell runs any CLI binary.
  - Tests read each CLI only from its synthetic fixture.
  - Secrets in any CLI's settings are never read into the UI.
- **MC-R14. Vocabulary (MC13).** `PRODUCT.md` and `GLOSSARY.md` define CLI as "any supported CLI". Labels never call a CLI an agent.
- **MC-R15. Wave definition of done (MC2, MC6, MC19, MC20, MC24, MC25).**
  - A wave ships one CLI in a normal release, with the `site/` copy naming it.
  - It ships only after `build-review` and either a real-install check or a recorded "not checked on a real install" with no release.
  - Waves follow the MC19 and MC20 order. A wave with unverifiable formats is skipped and recorded.
- **MC-R16. Sequencing (MC7).** Step 0a (MC-R1) changes no wire shape, so it can land beside the widget. Step 0b (MC-R2) starts after the widget is on `main` and moves every widget read of `cli` to the open contract in the same commit.

## Inferred, not decided

- **Agent copy between Claude Code (`.md`) and Codex (`.toml`) stays.** Both declare the copy format `agentFields` (name, description, instructions, each written in the target's own file format), so today's frozen copy works unchanged. This is not the cross-format conversion MC5 rules out, because only those three fields move. Reading MC5 strictly would refuse it and change the mutate golden. Source: agent's choice in step 0b.
- **The CLIs group sits in Settings › Appearance**, after Session widget, with the existing row and switch, not in a new rail section. Pages still show a CLI that is not installed (Gemini CLI on Limits), as before. Hiding uninstalled CLIs (MC3) waits for the wave that adds the first such CLI. Source: agent's choice in step 0b.

- **"Absent" and "not measurable" are two different readings.** A concept the CLI does not have is absent. A concept it has but does not log is not measurable. Source: the agent's reading of MC1 against [PRODUCT.md](../../PRODUCT.md).
- **Root env overrides** (`COPILOT_HOME`, `CURSOR_CONFIG_DIR`, `OPENCODE_DB`) are honoured where a CLI documents one, like `CLAUDE_CONFIG_DIR` and `CODEX_HOME` today. Source: agent's choice.
- **Cline CLI's** config and log formats were not verified on 2026-11-19, and neither were **Antigravity's** paths. Their waves begin with that check. Source: research gaps.

## Out of scope

- IDE extensions and IDEs: the Cline VS Code extension, Cursor IDE and Windsurf. The cloud agents Devin and Jules.
- Amp, Kiro CLI and Aider (MC4).
- Converting an item from one CLI's format to another's (MC5).
- The app-wide layout detail. This spec only requires that the layout carries a variable set of CLIs (MC3).
- Guessed numbers of any kind (MC1).
- Platforms other than macOS.
