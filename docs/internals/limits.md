# Limits

How the app knows how much of each subscription's usage Window is left. Claude Code figures come from its usage cache or from status-line snapshots that `spacevibe statusline capture` records; Codex figures come from its session logs; Gemini CLI keeps none, and the app says so. The Limits page and the sidebar tiles read this result. Terms follow [GLOSSARY.md](../../GLOSSARY.md); the wire shape is in [core-protocol.md](core-protocol.md#wire-types) and is not repeated here.

## Where each fact comes from

| Fact | Read from |
| --- | --- |
| Claude Code, usage cache | `cachedUsageUtilization` in `<CLAUDE_CONFIG_DIR or HOME>/.claude.json` (`State` of Claude Code's `roots.CLIRoots`, from the registry's `StateFile`): `fetchedAtMs` and `utilization.limits[]` with `kind`, `group`, `percent`, `resets_at` (ISO text), `scope.model.display_name`, `is_active`. Claude refreshes it only when it fetches usage itself |
| Claude Code, snapshot | `<data>/claude-limits/<session_id>.json`, written by capture from the `rate_limits` of the status-line input: `account` (hash), `observedAt`, and `five_hour` and `seven_day`, each `used_percentage` and `resets_at` (integer seconds). At most 4096 bytes each, newest 64 kept |
| Codex | Last `token_count` line of `<CODEX_HOME>/sessions/**` (`.jsonl` or `.jsonl.zst`): `timestamp`, `payload.rate_limits.primary` and `secondary` (`used_percent`, `window_minutes`, `resets_at` or the older `resets_in_seconds`), `plan_type` |
| Gemini CLI | Whether `~/.gemini` exists; nothing inside it is read |
| Window length | Snapshot: 300 and 10080 minutes by key. Cache: from `group` or the `kind` prefix, `null` for any other name. Codex: `window_minutes`, `null` when absent |
| When it was taken (`at`) | Cache `fetchedAtMs`; snapshot `observedAt`, the collector's own clock; Codex the event `timestamp` |
| Reset time | Seconds since 1970 everywhere. The cache's ISO text is parsed with its offset, and text with no zone is read as UTC. The core uses no local time |
| Plan | Codex `plan_type` only; Claude Code names none |

## Runtime path

1. Install. The user pastes `'<helper>' statusline install` into a terminal (the app only copies it). `runInstall` resolves the roots, then `Install` reads the running executable and edits Claude's `settings.json` in one journaled edit: `statusLine.command` becomes the wrapper around the previous command. Only after that succeeds is the executable written to `<data>/bin/spacevibe`; if the write fails the edit is undone. Uninstall is one journaled edit that sets the previous command back, or removes `statusLine` when there was none.
2. Capture. Claude runs the wrapper with the status-line JSON on stdin. `runCapture` starts `/bin/sh -c <original>`, forwards stdin to it, and keeps up to 1 MiB of the input. At end of input `collect` resolves the roots, checks the Claude root, and `Capture` writes the snapshot atomically (0600) and prunes to 64 files. A failure writes a reason to `last-error`; a success deletes it. The process then exits with the original's status.
3. Read. `limits.Read` builds the Claude entry (cache, then snapshots, see below), the Codex entry from the newest three logs by modification time, and the Gemini entry, then sets each window's `current`. The shell turns `usedPercent` into the share left and decides staleness.

## Rules that are easy to get wrong

- **Every percentage in the core is used, never left.** Snapshot `used_percentage`, cache `percent` and Codex `used_percent` all arrive as `usedPercent`; only the shell computes `100 - usedPercent` ([`LimitsWording.shareLeft`](../../Sources/SpaceVibe/Limits/LimitsWording.swift)). Capture rejects a snapshot window outside 0 to 100, but cache and Codex values can pass 100. Do not subtract or clamp in the core, and do not show `usedPercent` as a remaining share (W23).
- **A reached reset makes a window unknown, and age alone never does.** `current` is `resetsAt > now` at read time; the core still returns the window as recorded. The core has no age limit on a reading: a snapshot is trusted until its reset passes. "Stale" is a shell rule, `LimitsWording.staleAfter` (6 hours). Do not add a freshness cutoff in the core, and never show a passed window as 0 used.
- **A snapshot replaces the cache whole, unless the cache fetch is strictly newer.** `readClaude` takes the snapshot reading when the cache is not `measured` or its `at` is not later than the newest snapshot's. The result then holds only `five_hour` and `weekly_all`: the cache's per-model windows (`scope`) disappear, and an unreadable cache stops showing as unreadable. Do not merge cache windows into a snapshot reading without changing this rule and its tests ([statusline_test.go](../../core/internal/limits/statusline_test.go) `TestStatuslineNewerCacheWins`).
- **Snapshots from several sessions merge so usage never moves backwards.** Only snapshots within 3600 s of the newest are used, and for each window the highest `used_percentage` among those with the newest reading's reset time wins, so an idle session repeating an old value changes nothing, while a new reset time starts clean. A window that only an older snapshot reported is dropped. Snapshots with an `observedAt` after `now` are ignored ([`TestStatuslineIdleSessions`](../../core/internal/limits/statusline_test.go)).
- **A snapshot counts only for the account that wrote it.** `account` is the SHA-256 of Claude root, `accountUuid` and `organizationUuid`; no id is stored. A snapshot with another hash is skipped, and a session first captured under another account is never overwritten by `Capture`. With no `accountUuid` in the state file, capture fails with `account-unknown` and reads fall back to the cache. `CachedAccountKey` only avoids re-parsing a state file of up to 64 MiB on every capture; it is invalidated by the file's path, size, mtime and root, and is never a source of truth. Keep both sides on `AccountKey`.
- **Only text that `Quote` wrote counts as a wrapper.** `unwrapOnce` accepts exactly `'<dir>/bin/spacevibe' statusline capture '<data>' '<claude>' '<original>'` (and the older `reins-statusline --capture` form), up to 8 levels deep. Any other shape, such as an extra space or a shell operator, is the user's own command and gets wrapped. Build wrapper text only with `WrapperCommand` and `Quote`, so the original reaches `/bin/sh -c` byte for byte. The data root and Claude root are pinned in the command: if `CLAUDE_CONFIG_DIR` differs when Claude runs it, capture records `claude-root-changed` and writes nothing until the user reinstalls.
- **Capture is invisible to Claude.** The original gets the process's own stdout and stderr and its exit status is returned (a signal as 128 plus the signal); stdin is forwarded whole even past the 1 MiB keep limit. Capture adds at most one fixed sentence on stderr. It ignores SIGPIPE with `signal.Notify`, not `signal.Ignore`, because an ignored signal would be inherited and the original would no longer die of SIGPIPE as it does under Claude. The original stays in Claude's process group, so cancelling the status line cancels it. Do not start a new group or print anything else ([command_test.go](../../core/internal/statusline/command_test.go)).
- **One entry in an unknown shape makes the whole reading unreadable, not partial.** A cache entry, a Codex `primary` or `secondary`, or a snapshot window that fails validation is never shown alone, because the one left out may be the nearly used-up Window. Codex lines are matched as the compact text `"type":"token_count"` and `"rate_limits":{` before parsing, so a log written with spaces reads as `notRecorded`, and `rate_limits:null` lines are skipped. Codex logs are chosen by modification time, not date folder, since a resumed session appends to an old file.

## Failure behavior

- **No snapshot yet.** Claude reads from the cache. No cache but a Claude folder gives `notRecorded`, no folder gives `notInstalled`; a Claude state file that cannot be read, is past 64 MiB or is not JSON gives `unreadable` (a good snapshot cannot rescue it, since the account key needs the same file).
- **Stale snapshot.** Returned as recorded until its reset passes, then `current: false`; the shell adds the 6 hour warning.
- **Capture fails.** The original still runs and prints as before. The reason code (`input-too-large`, `claude-root-changed`, `account-unknown`, `write-failed` and so on, see [last-error.go](../../core/internal/statusline/last-error.go)) replaces `<data>/claude-limits/last-error`, and a later good capture deletes it. No screen reads this file; it is for a person debugging by hand. Input with no `rate_limits` is normal before the first reply and is not a failure.
- **The original fails or cannot start.** Its output and exit status pass through and the snapshot is still taken. If `/bin/sh` cannot start it, capture prints one sentence and exits 1; an empty original exits 0 and prints nothing.
- **Broken pipe.** If the original stops reading, forwarding stops writing but keeps draining stdin, so the snapshot still sees the whole input.
- **Corrupt snapshot.** A file over 4096 bytes, not JSON, a FIFO, a link or not named `<session>.json` is skipped; the next snapshot or the cache answers. A `claude-limits` folder that is a link out of the data root, or not private to the user, is neither read nor written.
- **A CLI that reports nothing.** Codex with no usable rate-limit line in its newest three logs reads `notRecorded` (`unreadable` if a log could not be read and none gave a line). Gemini CLI reads `notMeasurable` when its folder exists and `notInstalled` otherwise. None of these is a number.

- `cd core && SPACEVIBE_TEST=1 go test -count=1 ./internal/limits/... ./internal/statusline/...` runs [limits_test.go](../../core/internal/limits/limits_test.go), [statusline_test.go](../../core/internal/limits/statusline_test.go), [hardening_test.go](../../core/internal/limits/hardening_test.go), [golden_test.go](../../core/internal/limits/golden_test.go), [install_test.go](../../core/internal/statusline/install_test.go), [capture_test.go](../../core/internal/statusline/capture_test.go), [command_test.go](../../core/internal/statusline/command_test.go) and [rpc-cannot-capture_test.go](../../core/internal/statusline/rpc-cannot-capture_test.go), all on temporary homes. `SPACEVIBE_TEST=1` makes `roots.Resolve` and the write guard refuse any root under the real home (S-R1); `scripts/test.sh` sets it.
- [scripts/test-statusline.sh](../../scripts/test-statusline.sh) builds the core and drives the real binary in a synthetic home, with python3: exact stdout, stderr and exit status, the size cap, `last-error`, early pipe close, process-group cancellation, default SIGPIPE, install and uninstall. `scripts/test.sh` does not run it; run it by hand after changing `command-capture.go`.
- Per-OS files: [exit-status_unix.go](../../core/internal/statusline/exit-status_unix.go) and [exit-status_other.go](../../core/internal/statusline/exit-status_other.go). Off unix there is no `/bin/sh` and no SIGPIPE, so capture only reports a failure.
