# SpaceVibe design language

The shipped interface is the v5 shell: Agents (Skills, Subagents, Hooks, Rules), Activity and Limits. It is the same in development and distribution builds; no UI environment switch is required. [Registry](../Sources/SpaceVibe/Shell/TabRegistry.swift), [app shell](../Sources/SpaceVibe/Shell/AppShell.swift), [design decisions](specs/2026-11-06-reins-design-language-v5.md).

## Screens compose shared components

Visual decisions belong in [Tokens](../Sources/SpaceVibe/Tokens) and [Components](../Sources/SpaceVibe/Components). Agents, Skills, Subagents, Hooks, Rules, Activity, Limits, Shell and Settings only compose them. [StyleBoundaryTests](../Tests/SpaceVibeTests/StyleBoundaryTests.swift) rejects local fonts, colours, spacing and paint; [PointerCursorPolicyTests](../Tests/SpaceVibeTests/PointerCursorPolicyTests.swift) requires shared controls to own the pointer. Inventory models remain shared under [Agents](../Sources/SpaceVibe/Agents).

## Type and colour

Inter is the only bundled font. Each [text role](../Sources/SpaceVibe/Tokens/SpaceVibeType.swift) owns its size, weight, line box, tracking and font features; [TypeScale](../Sources/SpaceVibe/Tokens/TypeScale.swift) applies the Settings font-size choice. Screen code chooses a semantic role rather than supplying a size.

[Palette](../Sources/SpaceVibe/Tokens/Palette.swift) owns dark and light colours. Green, amber and red communicate state; category identity and CLI identity remain distinct from state. [CLIRegistry](../Sources/SpaceVibe/Components/CLIRegistry.swift) holds only each CLI's look (brand mark and tone token), keyed by the core's id; every other per-CLI fact (name, concepts, item kinds, limits reading, hook-run logging) comes from the core's `clis.list`. [CLICatalog](../Sources/SpaceVibe/Components/CLICatalog.swift) joins the two, drops the CLIs the owner turned off in Settings > Appearance > CLIs, and filters every core result before a page reads it, so an id the core did not list never shows. Views ask `cli.identity` or the catalog's lists and never name a CLI, which [CLIBranchPolicyTests](../Tests/SpaceVibeTests/CLIBranchPolicyTests.swift) enforces. To add a CLI's look, add its id constant and its entry to the registry, its tone to `PaletteValue` and its mark to `Resources/Brand`; [CLIRegistryTests](../Tests/SpaceVibeTests/CLIRegistryTests.swift) fails until every CLI `clis.list` returns has a complete look whose tone is neither a state colour nor the accent. A CLI the core lists without a look still shows, with the registry's neutral look (no mark, the `fg2` dot), never another CLI's. `sessionWorking`, `sessionWaiting` and `sessionDone` in [Palette](../Sources/SpaceVibe/Tokens/Palette.swift) are state colours too: they belong to Activity's session states as the glance widget draws them, and unmeasurable or idle sessions use `mute`. [ContrastTests](../Tests/SpaceVibeTests/ContrastTests.swift) checks composite surfaces and visible focus; [HuePolicyTests](../Tests/SpaceVibeTests/HuePolicyTests.swift) checks category and state separation.

## Layout and interaction

[AppShell](../Sources/SpaceVibe/Shell/AppShell.swift) keeps inactive pages mounted, but hides them from input and accessibility. Settings covers the page, while the command palette and confirmations occupy the window overlay. [TabRegistry](../Sources/SpaceVibe/Shell/TabRegistry.swift) owns sidebar order and Command-number navigation; Limits is a regular tab.

[Metrics](../Sources/SpaceVibe/Tokens/Metrics.swift) owns component dimensions. [SplitCanvas](../Sources/SpaceVibe/Components/SplitCanvas.swift) shares available height between summary cards and the main list and stacks them at narrow widths. [ListPaneLayout](../Sources/SpaceVibe/Components/ListPaneLayout.swift) owns the Skills list and detail pane. These layouts remain distinct; the scratch HTML proposals made on 2026-11-12 have not been adopted.

[LogoToggle](../Sources/SpaceVibe/Components/LogoToggle.swift) still represents per-CLI installation and guarded add/remove actions. [WarningSlot](../Sources/SpaceVibe/Components/WarningSlot.swift) exposes the explanation and related actions through its popover. [FocusFill](../Sources/SpaceVibe/Components/FocusFill.swift) keeps focus visible on selected rows. These are shared contracts, not per-screen styling choices.

[ToastHost](../Sources/SpaceVibe/Shell/ToastHost.swift) owns the toast placement and Undo key. The newest journal write can be undone after its toast disappears; Activity dismissal has its own in-memory Undo. Stop uses [StopSessionPanel](../Sources/SpaceVibe/Activity/ActivityStopConfirmation.swift), identifies the process and consequence, and has no Undo.

Settings composes the same blocks as the other pages ([Tile](../Sources/SpaceVibe/Components/Tile.swift), [ListRow](../Sources/SpaceVibe/Components/ListRow.swift), [ActionButtonStyle](../Sources/SpaceVibe/Components/ActionButtonStyle.swift), [StatusBar](../Sources/SpaceVibe/Components/StatusBar.swift)) plus its own [RailTab](../Sources/SpaceVibe/Components/RailTab.swift), [ThemeTile](../Sources/SpaceVibe/Components/ThemeTile.swift), [SegmentedControl](../Sources/SpaceVibe/Components/SegmentedControl.swift) and [SpaceVibeSwitch](../Sources/SpaceVibe/Components/SpaceVibeSwitch.swift) on the same tokens. Every glyph comes from MingCute or Phosphor ([IconPolicyTests](../Tests/SpaceVibeTests/IconPolicyTests.swift)). A component is removed only when no current surface or supporting data contract uses it.

## Gallery and verification

[ComponentGallery](../Sources/SpaceVibe/Gallery/ComponentGallery.swift) renders current containers, controls, glyphs, the Skills pane and Settings specimens. Gallery and screenshot launch modes remain development-only through [LaunchMode](../Sources/SpaceVibe/App/LaunchMode.swift); promoting the UI does not enable those modes in distributed builds.

Use `SPACEVIBE_SHOT_SCREEN=<screen> scripts/dev-fixture.sh --shots <dir>` with `shell`, `skills`, `subagents`, `hooks`, `rules`, `activity`, `limits`, `settings` or `glance`. The [fixture wrapper](../scripts/dev-fixture.sh) supplies synthetic roots, and the [renderer](../Sources/SpaceVibe/Gallery/ShotRenderer.swift) rejects real-screen shots without the test guard. Static checks and headless shots do not establish live keyboard, VoiceOver or owner visual acceptance.
